## 一、一句话结论

上游是**在微信开发者工具里跑的小程序原型**（原生小程序页面 + 24 个云函数 + `DEMO_MODE` 本地演示数据）；本项目把它**重写为一个可独立部署的 H5 网页应用**——前端 Vue3，后端自建 Node 服务（83 个 REST 接口），**去掉了模拟支付，改为「锁单 + 线下交付」**，并按**华中农业大学**的真实校园场景做了定制。

## 三、产品逻辑改动

### 3.1 核心检索维度：课程匹配 → 专业 + 年级

上游的主线是 **course-aware（按课程号找书）**；本项目把它换成了**按「专业 + 年级」找书**。

- 上游：`getBooksForHomepage` / `getCategories` 等云函数围绕**课程号**组织内容。
- 本项目（提交 `feat(home): course matching replaced by major/grade recommendation`）：
  - `src/services/catalog.js` 维护华农真实专业目录：**53 个专业 + 6 个年级**，分 10 个学科组；首页荐书、发布表单、求购表单**三处共用同一份**。
  - 匹配策略逐级放宽：`专业+年级` → `专业` → `年级`，并在结果里明确告诉用户是精确命中还是放宽命中。
  - 命中后同时带出**同专业同学的求购帖**，"我有此书"把专业/年级上下文带进发布流程。

> 为什么改：华农的教材选择主要由培养方案（专业）+ 学期（年级）决定，课程号对学生的检索心智不友好；且二手书流转本身就是"同专业低年级接盘"。

### 3.2 交易闭环：模拟支付 → 锁单防抢 + 线下交付

- 上游 `createAndPayOrder` + `checkout` 是**课程演示用的模拟下单**（上游 README 明确写了 "does not invoke real payment"）。
- 本项目**彻底移除支付环节**，改为：
  - **确认购买 = 锁定教材，不扣款**（`locked`），商品对其他买家暂不可买，解决"两人同时想买谁先得"。
  - 订单状态机：`待面交 → 交易中 → 已完成`，另有 `已取消` 与**超时自动关闭**（`server/.t/test-timeout.mjs`）。
  - 买家"确认完成"后才置为已售；订单页为四种状态各配一段解释文案（锁/验/时/消）。
  - 首页轮播专设一页「**购买说明**」，讲清"确认购买不会立即扣款"——上线后用户最容易误解的点。

### 3.3 联系方式隐私：新增三档可见性

上游把联系方式直接显示在详情页；本项目改为**默认不对陌生人公开**：

- 用户自选三档（`contactVisible`）：`public` / **`order_only`（默认，仅交易对方可见）** / `private`。
- 不满足条件时详情页只显示**锁形占位**，且**服务端不下发真实号码**（不是前端 CSS 隐藏）。
- 明确区分"**登录邮箱 ≠ 交易联系方式**"，设置页与编辑资料页都写明，避免用户混淆。

### 3.4 学籍认证（新增）

上游没有这道门槛。本项目把"是不是本校学生"做成可运营的准入：

- 用户上传**企业微信**截图 → `未认证 / 待认证 / 已认证 / 已拒绝` 四态。
- 管理员逐条审核，**拒绝必须填理由**且理由对用户可见（用户端会收到结果弹窗）。
- **未认证不能发布、不能购买**，从源头压住校外倒卖与虚假挂单。

### 3.5 账号体系（上游依赖微信身份，H5 必须自建）

上游只有 `login` 云函数（拿 openid）。本项目补齐完整账号系统：

- 邮箱 + 密码注册；**6 位数字验证码**验证邮箱：密码学随机、**库里只存 HMAC 哈希**、5 分钟有效、错 5 次作废、一次性、重发 60 秒冷却；找回密码是匿名接口，**绝不回传验证码**。
- 登录安全：失败计数 + 锁定、IP/账号双维度限流、登录审计。
- 多设备会话管理；改密后**全设备下线**。
- **账号注销**（输"注销"二字 + 验密码双确认）：删除账号与资料，**历史订单匿名保留**，不影响交易对方查看。

### 3.6 管理后台（新增，36 个接口）

上游无配套后台。本项目补齐运营侧：数据概览、商品审核（通过/拒绝+理由）、商品编辑与删除、用户列表 → 详情下钻 → 处置、清理能力（登录记录/求购帖/订单/操作日志）、**运营位轮播后台可配**（标题/副标题/图片/跳转/启停/排序，首页前 n 页由它驱动）、邮件设置（SMTP 自检 + 测试发信）、存储统计、数据备份导出。

### 3.7 数据层：DEMO_MODE → 真实持久化后端

上游用 `DEMO_MODE = true` 走会话内数据。本项目自建 Node/Express（JSON 落盘、零原生依赖、Windows 可直接跑），并解决自建后端的运维问题：

- **代码与数据分离**：线上数据落在部署包之外，部署覆盖不到；首次上线自动迁移历史库。
- **自动备份**：启动迁移/结构升级前自动复制，保留最近 20 份。
- **部署护栏**：`scripts/deploy-guard.mjs prep / restore / status`，内置 SMTP 凭据固化检查。

另有 H5 特有的两个平台坑已在代码中注释留档：托管网关会覆盖 `Authorization` 头（业务 token 改走 `X-Auth-Token`）；托管部署不支持 ignore 文件（数据必须放在部署包外）。

## 五、⚠️ 本项目在开源前必须先处理的安全项

**这三条不修完就推公开仓库会造成实际损害**，已逐条实测确认：

| # | 问题 | 位置 | 风险 |
|---|---|---|---|
| 1 | **JWT 签名密钥写死** | `server/config.js` → `jwtSecret: 'hzau-bookcycle-…-v1（已从源码移除）'` | 源码公开 = **任何人可伪造管理员令牌接管线上后台**（线上确实在用这个密钥） |
| 2 | **调试端点泄漏密钥指纹** | 原 `server/index.js` `/api/debug/auth` | 线上**可匿名访问**，会回显 `secretFingerprint`（密钥前 8 位 + 后 4 位）与 token 片段 → 已于 2026-09-24 从源码移除，**需发布后线上才生效** |
| 3 | **真实个人手机号硬编码** | `src/services/contact.js` → `ADMIN_WECHAT = '151****8376'` | 真实号码随仓库公开，且被注册/重置密码/认证三个页面展示 |

另：`server/config.js` 的 `adminPassword` 默认值 `'hzau-admin-****'` 也是弱默认，建议改为无默认值 + 首次启动强制设置。

> 这三项属于本项目自建后端的实现问题，与上游代码无关；处理完再提交 PR。

## 六、建议的 PR 形态

上游是**小程序**，本项目是**独立 H5 + 自建 Node 后端**，两者代码不重叠。建议**新增 `h5-web/` 目录 + 说明型 PR**，不影响小程序主线。要点：

- **只推文本文件**：本地 `public/images/` 与上游 `images/` 的 54 个文件**同名同路径、零差异**，因此 `h5-web/` 内只需指向上游 `images/`（软链或拷贝脚本即可），**无需提交任何二进制**。
- 提交内容：`src/`（22 页面 + services + styles）、`server/`（Node 服务与测试套件）、`index.html`、`vite.config.js`、`package.json`、`.gitignore`、本说明。
- **必须排除**：`node_modules/`、`dist/`、`.git/`、`server/data/`、`server/uploads/`、`server/mail-config.json`、`server/mail-outbox.log`、`_runtime-at-deploy/`、`*.log`。
- PR 描述直接使用本文，开头写明第五节的安全项已处理。
- 建议同时在上游 `README.md` 增加一节「H5 版本（社区贡献）」指向该目录，便于读者发现；并补一个 LICENSE。

> 备选方案：本项目依赖与部署方式（Node 服务 + 包外数据目录）和小程序差异较大，**单独开仓库、在上游 README 挂链接**可能更清爽。无论哪种，都请先处理第五节。
