# 华农书循环 H5 · 账号系统设计说明

> 目标：把原来"扫码 clientId 静默登录"的演示写法，替换为可直接上生产的账号体系。

## 二、关键设计取舍

### 1. 令牌：JWT 访问令牌 + 数据库会话（而非纯 JWT）

- **取舍**：纯 JWT（原来的写法）签发后无法吊销——管理员禁用账号、用户改密、登出之后，旧令牌在过期前依然有效。这是原系统最致命的问题。
- **做法**：access token 仍是 JWT（2 小时，无状态校验快），但 refresh token 是**数据库记录**（30 天，可吊销、可批量吊销全部设备）。
- **代价**：每次刷新要查一次库。对一个校园二手书平台，这点开销远小于"登出后令牌还能用"的风险。

### 2. 刷新令牌轮换 + 重放检测

- 每次用 refresh token 换新，旧的**立即失效**。
- 若服务端收到一个已失效的 refresh token，判定为**令牌泄露重放**，把该用户整条会话链全部吊销，强制重新登录。
- 这是 OAuth 2.1 / NextAuth 的标准做法，防"令牌被偷后被长期冒用"。

### 3. 保留 `?token=` query 通道（被现实逼出来的妥协）

- 托管网关 `*.app.workbuddy.host` 会**剥离 Authorization 头**，自定义头 `X-Access-Token` 也被剥。
- 所以服务端同时解析三处：`Authorization: Bearer` / `X-Access-Token` / `?token=`。
- **代价与缓解**：query token 会进访问日志。生产自建域名时应只保留 header 通道——代码里已经把解析集中在一个函数，去掉一行即可。

### 4. refresh token 放 localStorage（而非 httpOnly Cookie）

- **取舍**：httpOnly Cookie 更安全（JS 拿不到，天然防 XSS 窃取），但需要同源部署 + CSRF 防护，而本项目前后端分离且网关会改请求。
- **做法**：refresh token 存 localStorage，配合严格的输入输出转义；同时靠**轮换 + 重放检测**把泄露后的危害窗口压到最小。
- 若后续自建域名同源部署，建议改成 httpOnly + SameSite=Strict Cookie。

### 5. 邮箱验证：可插拔适配器，默认开发模式

- 没配 SMTP 时，验证链接直接通过接口返回（开发/内网自测可用）。
- 配了 `SMTP_HOST` 等环境变量后自动走真实发信（nodemailer 运行期 require，没装也不崩）。
- 这样既不阻塞本地开发，也不会把"假发信"带到生产。

### 6. 防枚举：宁可牺牲一点体验

- 注册已存在邮箱、登录密码错误、找回密码——三者**返回完全相同的响应**与相近耗时（都走一次 bcrypt 比对），不泄露账号是否存在。
- 代价：用户"我是不是注册过"无法从接口判断，只能靠邮箱收信确认。这是安全上的正确取舍。

## 三、实现清单

### 后端

```
server/security.js   密码哈希/校验、强密码策略、邮箱昵称校验
                     滑动窗口限流、登录失败锁定、数据脱敏
server/mailer.js     邮件适配器（SMTP / 开发模式）
server/db.js         新增 sessions / emailTokens / resetTokens / securityLogs
                     旧 users 数据自动迁移
server/auth.js       optionalAuth / authRequired / adminRequired / approvedRequired
                     三通道令牌解析、令牌签发与轮换
server/index.js      账号 API 集合
```

### 账号 API

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/auth/register` | 注册，返回双令牌，发验证邮件 |
| POST | `/api/auth/verify-email` | 邮箱验证（一次性令牌） |
| POST | `/api/auth/resend-verification` | 重发验证邮件 |
| POST | `/api/auth/login` | 邮箱 + 密码登录 |
| POST | `/api/auth/refresh` | 刷新令牌轮换 |
| POST | `/api/auth/logout` | 登出（吊销当前会话） |
| POST | `/api/auth/logout-all` | 全设备登出 |
| POST | `/api/auth/forgot-password` | 申请重置（防枚举） |
| POST | `/api/auth/reset-password` | 重置密码（一次性令牌，成功后全会话失效） |
| POST | `/api/auth/change-password` | 登录后改密（需原密码） |

### 防护参数

| 项 | 值 |
|---|---|
| 密码最小长度 | 8 位，且必须含字母与数字 |
| bcrypt cost | 10 |
| 访问令牌有效期 | 2 小时 |
| 刷新令牌有效期 | 30 天（每次轮换） |
| 登录失败锁定 | 5 次失败锁定 15 分钟 |
| 注册限流 | 同 IP 5 次 / 10 分钟 |
| 登录限流 | 同 IP 10 次 / 10 分钟 |
| 邮箱验证令牌 | 24 小时，一次性 |
| 重置密码令牌 | 1 小时，一次性，用后即焚 |

### 前端

- `src/services/server.js`：access/refresh 双令牌，401 自动无感续期（单飞锁避免并发重复刷新）
- `src/pages/Auth.vue`：登录 / 注册 / 找回三态
- `src/pages/EmailVerify.vue`：邮箱验证结果页
- `src/pages/ResetPassword.vue`：重置密码页
- 「我的」页：邮箱验证状态、改密、真登出（服务端吊销会话）

## 四、测试

| 套件 | 结果 |
|---|---|
| `server/.t/test-auth.mjs` 账号专项 | **37 / 37 通过** |
| `server/.t/test-api.mjs` 原有业务回归 | **59 / 59 通过** |
| 线上 E2E | **13 / 13 通过** |

线上 E2E 覆盖：注册即发双令牌 → 邮箱验证 → 已验证账号发布因未实名被拦（`NOT_VERIFIED`）→ 密码登录 → 错误密码 401 → 刷新轮换 → 旧令牌失效 → 重置密码 → 新密码可登录 → 登出 → 刷新失效 → 管理后台仍可访问。

## 五、上生产前还需要补的三件事

1. **配 SMTP 环境变量**（`SMTP_HOST` / `SMTP_PORT` / `SMTP_USER` / `SMTP_PASS` / `MAIL_FROM`），否则验证邮件发不出去，只能靠开发模式链接。
2. **改掉默认管理员密码**：`ADMIN_PASSWORD`，默认 `hzau-admin-****`。
3. **换持久化**：现在还是 JSON 文件库。会话表会持续增长，接 MySQL/Postgres 时只需替换 `server/db.js`（已做单文件隔离），并给 `sessions` 加过期清理任务。
